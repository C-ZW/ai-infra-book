# Book maintenance instructions

This directory contains the Traditional Chinese narrative nonfiction book **人類證明方法的演化：從計算、論證與實驗，到形式驗證與 AI**. Its source is `book-src/`; its generated, standalone reader is `web/index.html`.

## Before edits

Read `book-src/_meta/maintenance.md`, `style-guide.md`, and the affected chapter entry in `outline.md`. The exact chapter manifest is `chapter-manifest.json`. Read `workflow-adaptation.md` to understand which requirements from the repository's write-book v3 skill were adapted with the user's authorization. Do not label the adapted review as a completed original cross-model Tier-2 gate.

## Content invariants

- Keep all book prose and reader UI in Traditional Chinese (Taiwan usage); code, configuration keys, comments and validation logs are English.
- Mathematical proof is the central subject. Empirical evidence, causal inference, and legal judgment must retain their distinct warrants.
- Preserve theorem hypotheses, domain restrictions, model assumptions, historical edition/date qualifications and evidence provenance.
- Citation IDs are chapter-prefixed Markdown footnotes. All references and relative links must resolve.
- Use Unicode mathematics, not LaTeX delimiters. Do not hand-draw boxed diagrams or inject raw HTML into chapter sources.
- Edit the canonical baseline table in `outline.md` first, then regenerate its byte-identical copies in `running-examples.md` and the marked block of `maintenance.md`.
- `state.json` records actual work, not desired outcomes. A missing validator, unexecuted code, or inconclusive review is not a PASS.
- Never edit another book, the global writing skill, or generated root `bookshelf.html` merely to maintain this book.

## Build and validate

Use the book-local scripts documented in `scripts/README.md`. They require a supported Node runtime but no network package installation. Generated HTML is rebuilt from Markdown and the reader config; never edit it directly. Reader ID `proof-evolution-2026` was checked against the 27 reader configs in the repository at the base commit recorded in workflow-adaptation.md.

After content edits: reconcile the chapter manifest; run the deterministic gate and arithmetic checks; obtain an independent source/argument review of changed claims; rebuild the reader; verify its generated bytes and offline rendering. Record the actual commands and limitations in `book-src/_meta/verification-report.md` and the dated maintenance log. Repeat content-sensitive checks after substantive fixes.
